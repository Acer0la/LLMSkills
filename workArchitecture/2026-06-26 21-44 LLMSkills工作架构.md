## 3. 三个 Skill 的职责与协作

| Skill | 触发与职责 | 主要产出或约束 |
| --- | --- | --- |
| `Skills/firstinit/SKILL.md` | 对话开始或需要基础交互规则时使用 | UTF-8 读写 Skill；Skill 用英文维护；默认中文回复 |
| `Skills/checkpointsave/SKILL.md` | 重要任务开始读取工作规则和工作记录；有意义阶段结束时集中保存检查点 | 中文规则与记录，保存构建思路、已完成目标、后续目标和必要的结束提示 |
| `Skills/archsave/SKILL.md` | 重要任务开始读取架构记录；响应“整理工作架构”和“简述今天工作”等请求 | 中文架构文档；总体建设策略、大目标步骤、小目标流程、后续思路；按当日记录生成工作简述 |

典型协作流程：

1. 读取适用的全局 Skills，明确本轮规则。
2. 首次重要任务或缺少工作记忆时，读取全部已有架构文档、长期规则和工作记录，作为当前上下文。
3. 核对文件现状、Git 状态与当前请求，确定本次目标和验证方式。
4. 修改必要文件，完成与变更范围相称的验证。
5. 在整体工作或有意义阶段结束时集中保存检查点；结构或建设策略变化时更新架构入口。

不存在记录目录时，启动检查本身不要求创建目录；实际需要保存文档或检查点时再创建。

## 5. 维护规则

- 文件使用 UTF-8 读写。英文正式 Skill 文件 `SKILL.md` 的正文和 frontmatter 使用英文；同目录 `*-中文.md` 是中文母版，使用中文维护。工作规则、工作记录和架构文档也使用中文。
- 编码转换前必须先检查字节或 BOM 并确认源编码，不能凭显示效果或工具猜测编码。曾误将已是 UTF-8 的 `Skills/archsave/SKILL.md` 按 CP936 解码并重写，导致中文触发短语乱码及引号丢失；反向恢复也曾损失字符。确认需要转换后，须检查关键文本、确认没有 U+FFFD，并审阅完整差异；编码不明确时先暂停确认，不做猜测式重编码。
- `archsave` 中“整理工作架构”“简述今天工作”等中文触发词是用户明确要求的例外，其余 Skill 说明继续使用英文。
- 新增或调整 Skill 触发条件时，同步检查并必要时更新 frontmatter `description`，使其与正文一致。
- 修改 Skill 时保留原有结构、路径约定和行为意图，避免无关重写。
- Skill 创建或修改先以中文稿为起点：用户先提供中文稿，或与助手共同完善对应中文文档；中文稿与英文稿放在同一目录并按名称配对，例如 `<技能名>-中文.md` 对应 `<技能名>.md`。用户明确说“转换技能”后，才将已确认的中文稿翻译为对应英文 Skill 文档；翻译须尊重事实、准确、简洁。若仓库现有英文入口为 `SKILL.md`，沿用该入口，不擅自更名或改变目录结构。
- `workCheckpoint/Rules/` 保存长期约束，`Works/` 保存阶段过程与结果；历史路径变化应在当前架构入口解释，保留历史记录的上下文。
- 检查点在较大、总体工作或有意义阶段结束时集中保存，避免每次小改动都生成低内容文件。记录文件名使用“当前日期（精确到分钟）+ 操作重点.md”。
- 纯问答、很小的单文件修复、纯格式变更、已撤回的临时实验，不自动创建检查点。
- 保留任务开始前已有的用户改动；文件整理、全局安装和仓库提交均应遵守当前任务范围。

## 6. 目标分解与小目标工作流

| 大目标 | 当前状态 | 小目标工作流与完成标准 |
| --- | --- | --- |
| 建立基础约束 | 已有 `firstinit` 与长期规则 | 读取现有规则 → 核对编码与语言 → 按规则处理本轮请求 |
| 保持 Skill 职责一致 | 三个 Skill 已分工；`archsave` 已统一放入 `Skills/` | 明确触发场景 → 修改 description 与正文 → 校验结构与变更差异 → 无无关改动 |
| 支持中断、继续与交接 | 已有架构入口、规则和阶段记录 | 保存总体策略 → 拆分大目标及小流程 → 记录已完成、验证边界、后续目标 → 下次先读记录再核对现状 |
| 管理安装副本 | 本次三个文件哈希一致；无自动同步流程 | 明确需同步的文件与目标 → 执行授权范围内的安装或同步 → 比较内容 → 在实际会话验证所需行为 |
| 持续维护代理模板 | 普通与子代理模板均已存在 | 确认模板适用场景 → 核对模型和指令可用性 → 检查生效配置 → 验证当前会话行为 |

新增或修改 Skill 的日常流程：

1. 读取现有 Skill、工作规则、架构和相关历史记录，明确要解决的具体问题及中英文文件配对关系。
2. 如果目标英文 Skill 尚无中文稿，先将同目录英文原版译为 `<技能名>-中文.md`，建立未来母版。
3. 后续先与用户共同创建或修改同目录中文母版；此阶段不直接改写英文 Skill。
4. 仅在用户明确说“转换技能”后，将确认过的中文稿翻译为对应英文 Skill 文档；表达须尊重事实、准确、简洁。
5. 检查 frontmatter 与目录结构；触发语义变化时同步检查 `description`，并保留用户指定的中文触发词例外。
6. 运行适用的 Skill 校验和 `git diff --check`，审查最终差异。
7. 形成有意义阶段后保存一条汇总检查点；需要安装时单独说明目标和内容。
