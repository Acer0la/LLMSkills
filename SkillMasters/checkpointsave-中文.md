# CheckpointSave

## 强制启动检查

在回答或编辑任何编码、审查、重构、架构、调试、项目规则或其他重要工作之前：

读取或修改文件时使用 UTF-8 编码。

1. 如果这是当前工作区的首个重要任务，或工作区工作记忆不可用，先阅读本 Skill。
2. 如果 `./workCheckpoint/Rules/` 存在，读取其中所有 Markdown 文件。
3. 如果 `./workCheckpoint/Works/` 存在，读取其中所有 Markdown 文件。
4. 将这些记录作为后续工作的有效上下文。
5. 如果这些目录不存在，除非之后确实需要保存检查点，否则继续处理而不创建目录。

## 1. 记录工作

- 保存规则：每当用户提供对项目有长期影响的重要信息，例如编码规范、项目架构、文件架构、文件或文件夹命名约定、变量命名约定、工作流或其他规则时，应在下述目录中记录。记录应简短，同时保留核心含义。
- 保存工作记录：仅在较大或总体工作、或有意义的工作阶段完成后，记录操作过程和关键要点。将相关改动合并为一条简洁检查点，避免每次小改动都单独建档。当有助于中断后继续或交接时，也应记录当前目标的构建思路、已完成目标和后续目标。回复中报告：“Checkpoint recorded.”
- 保存规则：工作规则使用中文记录。
- 保存工作记录：工作记录使用中文记录。

文件保存规则：

- 文档格式为 `.md`。
- 可以使用 Markdown 转义字符。
- 文件名格式为“当前日期（精确到分钟）+ 操作重点”。

- 保存规则：将文档保存在当前工作目录下的 `./workCheckpoint/Rules/`。如果该目录不存在，可以创建。如果工作规则记录此前保存在根目录，应将它们移入此目录。
- 保存工作记录：将文档保存在当前工作目录下的 `./workCheckpoint/Works/`。如果该目录不存在，可以创建。如果工作记录此前保存在根目录，应将它们移入此目录。

## 2. 任务开始时的自动触发

如果没有关于此工作区的工作记忆，或这是本轮对话中的首个代码任务、审查或其他重要任务，且尚未读取工作规则（`workCheckpoint\Rules`）或工作记录（`workCheckpoint\Works`），则读取并记住这些记录。这一点很重要。

## 3. 任务结束时的自动触发

在较大或总体工作、或有意义的工作阶段结束时，如果满足以下任一条件，则自动使用本 Skill：

- 创建了新的源代码文件或模块。
- 修改了三个或更多项目文件。
- 新增了功能、子系统、命令、数据库或存储结构，或持久化数据格式。
- 修改了编译、构建或运行时集成逻辑，例如 includes、callbacks、routes、migrations 或 configuration。
- 用户明确强调了未来维护、交接、编码、项目约定，或提出“记录/记住/checkpoint”。
- 工作中发现了值得留存的非显而易见推理、重要约束或说明。

以下情况不自动使用本 Skill：

- 纯问答且未修改文件。
- 很小的单文件修复。
- 仅格式调整。
- 最终已撤回的临时实验。

自动触发时，在最终回复前保存检查点，并简要说明检查点路径。

- 对编码任务，在最终回复前检查本次修改的文件数量，以及是否新增模块或持久化格式。
- 如果已完成的工作较大、属于整体工作或有意义的阶段，并满足上述触发条件，直接创建检查点，无需询问。
- 保存任务结束检查点时，如果结束提示对后续继续或交接有帮助，应一并记录。
- 保存任务结束检查点时，如果有助于中断后继续或交接，应包括当前目标的构建思路、已完成目标和后续目标。
